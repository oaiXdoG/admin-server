# 服务发现改造（管理后台）

总规则见 danmu-login `docs/service-discovery.md`，本文是管理后台这一侧的改动清单和验收项。进程与服务绑定的整体方案见 admin-front `docs/service-binding-plan.md`。

改造后后台不再读 ZooKeeper：各项目的业务服（登录服、回调服、游戏服）用 HTTP 定时上报到后台，后台按 `App Key → instanceId` 两层 key 保存；「按区自动发现」数据源从这份上报数据里取游戏服（`type=logic`）各区的查询接口地址，进程管理按 `instanceId`（后台托管的进程为后台进程 ID）把上报绑定到进程。后台是一个进程管理所有项目，所有项目的业务服都上报到同一个地址。

## 1. 删除

| 内容 | 说明 |
| --- | --- |
| `ZoneDiscoveryService` 中的 Curator 客户端、`client()`、`close()` 和读 `/danmu/<appKey>/logic` 的代码 | 改为读上报数据 |
| `ApplicationProperties.zookeeperAddress` 和配置项 `zookeeper.address` | 后台不再连接 ZooKeeper |
| `ErrorCode.ZOOKEEPER_NOT_CONFIGURED(100086)` | 不再使用；admin-front 中没有引用 |

## 2. 上报接口

### 2.1 路由

`POST /api/node/report`，不需要登录（不校验 `Authorization`），按签名鉴权。

- 在 `Application` 路由表中注册（`parseNodeReportRequest`）：请求体在进入控制器前已释放，先把请求体的 SHA-256 写入内部请求头（`AgentService.BODY_DIGEST_HEADER` 的做法，覆盖客户端传来的同名头），再解析为 `NodeInfoReportRequest`，并把原始请求体放进 `raw`（`@JsonIgnore`，不从请求体读取）。
- 请求类 `NodeInfoReportRequest`（`@JsonIgnoreProperties(ignoreUnknown = true)`，不认识的字段忽略，节点新增字段时后台不用先升级）字段：`String type`、`String nodeId`、`Integer serverId`、`String instanceId`、`String host`、`Integer port`、`String innerHost`、`Integer gmPort`。字段只增不改。

请求体：

```json
{
  "type": "logic",            // 必填：login / callback / logic 等，对应进程类型编码
  "nodeId": "logic-1",        // 可选：zfoo 节点 ID，只用于显示
  "instanceId": "12",         // 必填：有 ADM_INSTANCE_ID 用它，否则随机 UUID
  "serverId": 1,              // 只有 type=logic 时必填（> 0），表示区号；其他类型可空
  "host": "111.230.143.165",
  "port": 9020,
  "innerHost": "10.0.0.8",
  "gmPort": 9021              // 没有 GM 接口填 0
}
```

### 2.2 验签

请求头：

| 请求头 | 值 |
| --- | --- |
| `X-Admin-Project` | 项目 App Key |
| `X-Admin-Timestamp` | 毫秒时间戳 |
| `X-Admin-Signature` | `hex(HMAC-SHA256(上报密钥, 时间戳 + "\n" + hex(SHA256(请求体))))`，小写十六进制 |

规则：

1. 按 `X-Admin-Project` 找项目；找不到 → 拒绝。
2. 用项目上报密钥（`project.report_secret`，`SecretCipher` 加密保存）解密后计算签名，与 `X-Admin-Signature` 相同即通过（`MessageDigest.isEqual` 比较）；项目还没有上报密钥 → 拒绝。不再读数据源密钥。
3. `|当前时间 - 时间戳| > 5 分钟` → 拒绝。
4. 签名计算复用 `BusinessClient.sign`、`AgentService.digest`。
5. 拒绝时返回 `NODE_REPORT_DENIED(100088, "节点信息上报验签失败")`，打印警告（App Key、instanceId、来源 IP、原因），同一 App Key + 来源 IP 每分钟最多打印一次。

上报密钥：项目首次需要时自动生成（进程管理「上报配置」查看、Agent 心跳下发进程定义时），可在「上报配置」里重置（`/api/server/report-config/reset`）。后台托管的进程由 Agent 注入 `ADM_REPORT_SECRET`、`ADM_REPORT_URL`、`ADM_INSTANCE_ID`，见 `docs/server-management.md`「服务绑定」。

### 2.3 参数校验

`type` 非空；`type=logic` 时 `serverId > 0`；`instanceId`、`host`、`innerHost` 非空；`port`、`gmPort` 在 0～65535。不合法 → 返回 `INVALID_REQUEST`。

### 2.4 存储：`NodeInfoReportService`

内存表：

```text
ConcurrentHashMap<String appKey, ConcurrentHashMap<String instanceId, Node>>
Node = { type, nodeId, instanceId, serverId, host, port, innerHost, gmPort, raw（原始请求体 JSON 对象）, reportTime }
```

- 每次收到按 `instanceId` 直接覆盖（不做区 ID 冲突判断，冲突由登录服、回调服拦截）。
- 在线：`当前时间 - reportTime ≤ 30 秒`。
- 超过 1 天没有上报的记录在该项目下次收到上报时清掉（实例 ID 随机的进程每次重启都会产生新记录），不加定时任务。
- 后台重启后表为空，业务服 10 秒内重新上报补齐。
- 后台按单进程部署；以后多实例部署时要改为放 Redis。

## 3. `ZoneDiscoveryService.zones(appKey, publicNetwork)`

方法签名和返回值 `List<Zone(zoneId, url)>` 不变，`DataSourceService` 不用改：

- 数据来自 `NodeInfoReportService` 中该 App Key 的在线记录，只取 `type=logic`。
- 区 ID 取上报的 `serverId`；同一个区有多条在线记录时取 `reportTime` 最新的一条。
- 只返回 `gmPort > 0` 的区。
- `url`：`publicNetwork=false`（连接方式「内网」）为 `http://<innerHost>:<gmPort>`；`publicNetwork=true`（「公网」）为 `http://<host>:<gmPort>`。
- 按区 ID 排序；没有记录返回空列表（调用方仍按原逻辑返回 `ZONE_NOT_AVAILABLE`）。

## 4. 部署

- 上报地址为后台对外地址（`agent.base-url`）加 `/api/node/report`，业务服所在服务器要能访问到。托管进程由 Agent 注入，不用配置。
- 数据源的连接方式（内网/公网）含义不变：后台访问游戏服 GM 接口时用哪个地址；数据源密钥只用于 GM 接口。

## 5. 验收项

| # | 场景 | 预期 |
| --- | --- | --- |
| 1 | 后台配置中没有 `zookeeper.address` | 正常启动，「按区自动发现」数据源可用 |
| 2 | 游戏服用项目上报密钥正确签名上报 | 返回成功；数据源「测试连接」能看到该区 |
| 3 | 签名错误 / 时间戳超过 5 分钟 / App Key 不存在 / 项目没有上报密钥 | 返回 `100088`，不保存 |
| 4 | 参数不合法（如 `type` 为空、`type=logic` 且 `serverId=0`） | 返回 `INVALID_REQUEST` |
| 5 | 两个项目各自上报 1 区 | 两个项目的数据源各自只看到自己的 1 区 |
| 6 | 同一实例重复上报 | 覆盖，只保留最新内容 |
| 7 | 游戏服停止超过 30 秒 | 数据源中该区消失（不在线），查询该区记为失败 |
| 8 | 同一区两个实例都在线 | 取最近上报的一条 |
| 9 | 上报 `gmPort=0` | 该区不出现在可查询列表 |
| 10 | 连接方式「内网」/「公网」 | 查询地址分别为 `innerHost:gmPort`、`host:gmPort` |
| 11 | 后台重启 | 10 秒内各区恢复 |
| 12 | 登录服、回调服上报（`type=login` / `callback`） | 不出现在按区发现里；托管进程显示服务在线 |
| 13 | 代码检查 | 后台没有任何 ZooKeeper / Curator 代码；`ErrorCode` 中没有 `100086` |
